# Сервис для работы с ПВЗ (Avito Тестовое)

Рад поприветсвовать того, кто это читает)

Я разработал backend-сервис на Go для управления пунктами выдачи заказов (ПВЗ), как требовалось в задании. 
Сервис позволяет сотрудникам ПВЗ и модераторам взаимодействовать с системой для учёта приёмки товаров, заказанных через Авито.


* **Управление ПВЗ:** Модераторы могут создавать новые ПВЗ (только в Москве, Санкт-Петербурге и Казани).
* **Управление приёмками:** Сотрудники ПВЗ могут инициировать и закрывать приёмки товаров. Нельзя начать новую приёмку, пока предыдущая не закрыта.
* **Управление товарами:** Сотрудники ПВЗ добавляют товары (электроника, одежда, обувь) в текущую открытую приёмку. Удаление товаров возможно только до закрытия приёмки и происходит по принципу LIFO.
* **Получение данных:** Модераторы и сотрудники ПВЗ могут получать список ПВЗ с пагинацией и фильтрацией по дате приёмки товаров.
* **Авторизация:** Реализованы два способа:
    * `/dummyLogin` для получения токена с ролью `employee` (сотрудник ПВЗ) или `moderator`.
    * Полная регистрация (`/register`) и авторизация (`/login`) по email/паролю с выдачей JWT-токена.

**ДОПОЛНИТЕЛЬНО:** В отличи от своего предыдущего проекта, я постарался продумать дальнейшее масштабирование и товары/города без хардкода.

## Структура проекта

Я постарался сделать структуру проекта понятной, оглядываясь на свой предыдущий проект.

* `cmd/api/main.go`: Главный файл приложения. Здесь инициализируются все компоненты (конфиг, логгер, база данных, репозитории, хендлеры), настраиваются роутеры (HTTP API, метрики, gRPC), запускаются серверы и реализуется graceful shutdown.
* `internal/`: Основная логика приложения.
    * `config/`: Загрузка конфигурации из переменных окружения (`.env` файл тоже поддерживается).
    * `db/`: Логика подключения к базе данных PostgreSQL.
    * `handlers/`: Обработчики HTTP-запросов и реализация gRPC-сервиса (`PVZService`). Содержат основную бизнес-логику, взаимодействуют с репозиториями.
    * `metrics/`: Определение и регистрация метрик Prometheus.
    * `models/`: Структуры данных (модели), используемые в приложении (User, PVZ, Reception, Product и т.д.).
    * `repository/`: Содержит интерфейсы и их реализации для взаимодействия с базой данных по каждой сущности (PVZ, User, Reception и т.д.). Работает с SQL.
    * `utils/`: Вспомогательные функции (хеширование паролей, работа с JWT).
* `pkg/api/`: Всё, что с OpenAPI.
    * `openapi.yaml`: Спецификация OpenAPI для эндпоинтов `/register` и `/login`.
    * `codegen.cfg.yaml`: Конфиг файл для `oapi-codegen`.
    * `generate.go`: Файл  для запуска кодогенерации DTO.
    * `dto.gen.go`: **Сгенерированный** код с DTO  для запросов и ответов API.
* `proto/`: Всё, что связано с Protobuf и gRPC.
    * `pvz.proto`: Определение gRPC-сервиса и сообщений.
    * `pvz.pb.go`, `pvz_grpc.pb.go`: **Сгенерированный** код Go из `.proto` файла.
* `tests/`: Интеграционные тесты.
    * `integration_test.go`: Тест, проверяющий основной сценарий работы сервиса.
* `Dockerfile`: 
* `docker-compose.yml`: 
* `init.sql`: SQL-скрипт для инициализации схемы базы данных и добавления начальных данных (разрешенные города, типы товаров).
* `loadtest.js`: Скрипт для нагрузочного тестирования с использованием k6.

## Как запустить проект

Для запуска понадобятся **Docker** и **Docker Compose**.

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL репозитория>
    cd <папка проекта>
    ```
2.  **(Опционально) Установите зависимости Go:** выполните:
    ```bash
    go mod tidy
    ```
3.  **Запустите сервисы с помощью Docker Compose:**
    ```bash
    docker-compose up --build
    ```

    * Сервисы будут доступны по следующим портам:
        * **HTTP API:** `http://localhost:8080`
        * **Prometheus Metrics:** `http://localhost:9000/metrics`
        * **gRPC Service:** `localhost:3000`
        * **PostgreSQL (для внешнего доступа, если нужно):** `localhost:5433` (внутри сети Docker используется порт 5432). Опять таки, как и в предыдущем проекте. Стандарт 5432 на моем устройстве уже занят, поэтому перекинул порты

4.  **Остановка сервисов:**
    ```bash
    docker-compose down
    ```

## Примеры cURL запросов

Здесь приведены примеры запросов к API с использованием `curl`.
* Вам нужно будет заменить плейсхолдеры вроде `<TOKEN>`, `<PVZ_ID>`, `<EMAIL>`, `<PASSWORD>` на реальные значения.
* Токены (`<TOKEN>`, `<EMPLOYEE_TOKEN>`, `<MODERATOR_TOKEN>`) можно получить через эндпоинты `/dummyLogin` или `/login`.
* ID ПВЗ (`<PVZ_ID>`) можно получить из ответа на запрос создания ПВЗ (`POST /pvz`).

**Аутентификация и Регистрация (Публичные)**

* **Получить Dummy токен:**
    ```bash
    # Получить токен сотрудника
    curl -X POST http://localhost:8080/dummyLogin \
    -H "Content-Type: application/json" \
    -d '{"role": "employee"}'

    # Получить токен модератора
    curl -X POST http://localhost:8080/dummyLogin \
    -H "Content-Type: application/json" \
    -d '{"role": "moderator"}'
    ```
    *Ответ будет содержать JSON с полем `token`.*

* **Регистрация нового пользователя:**
    ```bash
    curl -X POST http://localhost:8080/register \
    -H "Content-Type: application/json" \
    -d '{"email": "user@example.com", "password": "your_password", "role": "employee"}'
    # role может быть "employee" или "moderator"
    ```
    *Ответ будет содержать JSON с данными созданного пользователя (id, email, role).*

* **Вход пользователя:**
    ```bash
    curl -X POST http://localhost:8080/login \
    -H "Content-Type: application/json" \
    -d '{"email": "user@example.com", "password": "your_password"}'
    ```
    *Ответ будет содержать JSON с полем `token`, который нужно использовать в заголовке `Authorization: Bearer <TOKEN>` для защищенных запросов.*

**Управление ПВЗ (Требуется авторизация)**

* **Создать ПВЗ (Только модератор):**
    ```bash

    curl -X POST http://localhost:8080/pvz \
    -H "Authorization: Bearer <MODERATOR_TOKEN>" \
    -H "Content-Type: application/json" \
    -d '{"city": "Москва"}' # Допустимые города: "Москва", "Санкт-Петербург", "Казань"
    ```
    *Ответ будет содержать JSON с данными созданного ПВЗ, включая его `id`.*

* **Получить список ПВЗ (Сотрудник или модератор):**
    ```bash
   
    # Без фильтров и пагинации (используются дефолтные limit=10, offset=0)
    curl -X GET http://localhost:8080/pvz \
    -H "Authorization: Bearer <YOUR_TOKEN>"

    # С пагинацией
    curl -X GET "http://localhost:8080/pvz?limit=5&offset=10" \
    -H "Authorization: Bearer <YOUR_TOKEN>"

    # С фильтром по дате приёмки
    curl -X GET "http://localhost:8080/pvz?receptionDate=2025-04-14" \
    -H "Authorization: Bearer <YOUR_TOKEN>"

    # С фильтром и пагинацией
    curl -X GET "http://localhost:8080/pvz?receptionDate=2025-04-14&limit=20&offset=0" \
    -H "Authorization: Bearer <YOUR_TOKEN>"
    ```

**Управление Приёмками и Товарами (Только сотрудник ПВЗ)**

* **Создать новую приёмку:**
    ```bash

    curl -X POST http://localhost:8080/receptions \
    -H "Authorization: Bearer <EMPLOYEE_TOKEN>" \
    -H "Content-Type: application/json" \
    -d '{"pvzId": "<PVZ_ID>"}'
    ```
    *Невозможно создать, если уже есть открытая приёмка для этого ПВЗ.*

* **Добавить товар в открытую приёмку:**
    ```bash
    # (ПВЗ с открытой приемкой)
    curl -X POST http://localhost:8080/products \
    -H "Authorization: Bearer <EMPLOYEE_TOKEN>" \
    -H "Content-Type: application/json" \
    -d '{"type": "электроника", "pvzId": "<PVZ_ID>"}'
    # Допустимые типы: "электроника", "одежда", "обувь", но это в бд, как и города, так что в будущем можно это легко масштабировать. 
    ```

* **Удалить последний добавленный товар из открытой приёмки:**
    ```bash

    curl -X POST http://localhost:8080/pvz/<PVZ_ID>/delete_last_product \
    -H "Authorization: Bearer <EMPLOYEE_TOKEN>"
    ```

* **Закрыть последнюю открытую приёмку:**
    ```bash
    curl -X POST http://localhost:8080/pvz/<PVZ_ID>/close_last_reception \
    -H "Authorization: Bearer <EMPLOYEE_TOKEN>"
    ```

**Метрики Prometheus**

* **Получить метрики:**
    ```bash
    curl http://localhost:9000/metrics
    ```

**gRPC**

* **Получить список всех ПВЗ (используя grpcurl):**
    ```bash
    # Потребуется установка grpcurl
    grpcurl -plaintext localhost:3000 pvz.v1.PVZService/GetPVZList
    ```

## Кодогенерация

В проекте используется кодогенерация для двух вещей:

1.  **gRPC:** На основе `.proto` файла генерируется Go-код для сервера и сообщений.
2.  **OpenAPI DTO:** На основе `openapi.yaml` генерируются Go-структуры (DTO) для запросов и ответов эндпоинтов `/register` и `/login`.

Весь необходимый сгенерированный код уже **присутствует** в репозитории. Если вы хотите проверить процесс генерации вы можете перегенерировать код:

1.  **Для gRPC:**
    * Убедитесь, что у вас установлен `protoc` и плагины `protoc-gen-go`, `protoc-gen-go-grpc`.
    * **(Опционально)** Удалите старые сгенерированные файлы:
        * `proto/pvz.pb.go`
        * `proto/pvz_grpc.pb.go`
    * Выполните команду из **корневой папки проекта**:
        ```bash
        protoc --proto_path=proto \
               --go_out=paths=source_relative:. \
               --go-grpc_out=paths=source_relative:. \
               proto/pvz.proto
        ```
    * *Важно:* необходимо прописать go_package под структуру проекта (как и написано в требованиях :) )

2.  **Для OpenAPI DTO:**
    * Убедитесь, что у вас установлен `oapi-codegen`. 
    * **(Опционально)** Удалите старый сгенерированный файл:
        * `pkg/api/dto.gen.go`
    * Перейдите в директорию `pkg/api`:
        ```bash
        cd pkg/api
        ```
    * Выполните команду:
        ```bash
        go generate
        ```
    * Вернитесь в корневую папку проекта:
        ```bash
        cd ../..
        ```

## Тестирование

* **Unit-тесты:** Я использовал go test ./... -coverpkg=./cmd/...,./internal/... -coverprofile=coverage.out Чтобы не тестировать сгенерированный код. Он в тестах не нуждается, но проценты покрытия отъедает.
* 

   Чтобы запустить тесты.

  go test ./... -coverpkg=./cmd/...,./internal/... -coverprofile=coverage.out

  go tool cover -func=coverage.out



* **Интеграционный тест:** Находится в `tests/integration_test.go`. Запускается вместе с unit-тестами или отдельно `go test ./tests -v`.

**ВАЖНО:** Требует запущенного докера, но это и логично) 


* **Нагрузочное тестирование:** Используйте k6 и скрипт `loadtest.js`. (Требует к6 установленного)
    ```bash
    # Сначала получите токен модератора и сотрудника
    # Затем создайте ПВЗ через API модератором и получите его ID
    export MOD_TOKEN="токен_модератора"
    export EMP_TOKEN="токен_сотрудника"
    export PVZ_ID="id_созданного_пвз"

    k6 run --env MODERATOR_TOKEN=$MOD_TOKEN --env EMPLOYEE_TOKEN=$EMP_TOKEN --env PVZ_ID=$PVZ_ID loadtest.js
    ```
